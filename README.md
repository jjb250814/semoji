# 세모지 — 세상에 모든 쓸데없는 지식

공공데이터에서 캐낸, 알아도 인생에 도움 안 되는 사실들을 모으는 사이트.

차별점은 **출처가 정부 공식 데이터**라는 아이러니다. 인터넷 잡학은 출처가 없지만,
세모지의 지식은 원본 CSV를 직접 내려받아 계산한 값이다.

---

## 지금 어디까지 왔나

*(2026-09-03 기준. 이 문서 하나로 어느 PC에서든 이어서 작업할 수 있게 적어 둔다.)*

| | 값 |
|---|---|
| 열람실 | **10곳** (제1~10호) |
| 전체 페이지 | 14쪽 (랜딩 + 열람실 10 + 소개 · 연락처 · 개인정보처리방침) |
| 분석한 데이터셋 | 10개 · **818,919행** |
| 랜딩 지식 카드 | 54장 |
| 도메인 | `semoji.net`으로 정함 — **아직 구매 안 함** |
| 수익화 | AdSense 미신청 — **콘텐츠 요건은 충족.** 사이트가 아직 인터넷에 없다 |

**목표는 월 10~30만원짜리 자동화 파이프라인이다.**
AdSense 권장 분량은 글 10~15편 수준인데 열람실 10편 + 소개·연락처·개인정보처리방침으로
**14쪽이 되어 심사선을 넘겼다.** (예전에 20~30쪽이라 적어둔 건 과하게 잡은 수치였다.)
이제 막는 건 분량이 아니라 **사이트가 아직 인터넷에 없다는 것**이다.

**바로 다음 할 일 — 배포.** 도메인(`semoji.net`)을 사고 GitHub Pages에 올린다.
절차는 아래 「배포」에 있다. 열람실을 더 만들 거라면 후보는 이 문서 맨 아래
「다음 열람실 후보」에, 만드는 절차는 「열람실 하나 만드는 법」에 있다.

### 다른 PC에서 이어서 하려면

**대화 기록은 따라오지 않는다.** Claude Code의 대화는 프로젝트 폴더가 아니라
`%USERPROFILE%\.claude\projects\` 안에 저장되고, 그 폴더는 OneDrive 밖이다.
이 README가 인수인계 문서인 이유다.

새 PC에서는 이 폴더를 열고 `claude`를 실행한 뒤 이렇게 말하면 된다:

> README.md 읽고 이어서 제11호 만들자

같은 PC에서 어제 대화를 이어가려면 그 폴더에서 `claude --continue`,
여러 대화 중에 고르려면 `claude --resume`.

**떠나기 전에 `data/raw/`(약 4.4GB)를 지우는 게 좋다.** OneDrive가 그대로
동기화해서 다른 PC가 4.4GB를 내려받는다. 스캔 결과는 `광맥순위.txt`·`광맥상세.txt`에
텍스트로 남아 있으니 원본은 필요 없고, 필요하면 `scan_all.py`로 다시 받으면 된다.

HTML은 **의존성이 없다.** 더블클릭하면 그냥 열린다. 빌드도 서버도 필요 없다.
글꼴만 Google Fonts에서 가져오므로 오프라인에서는 대체 글꼴로 표시된다.

열람실 페이지는 CSS를 한 벌로 쓴다. 새 열람실은 `videoroom.html`의 `<style>` 블록을
그대로 물려받아 만들었다 (`restroom.html`이 그렇게 만들어졌다).

**미리보기 서버**는 `.claude/serve.py`가 **포트 8732**로 띄운다
(`.claude/launch.json`에 등록돼 있다). HTML을 더블클릭해도 열리지만,
서버로 봐야 상대경로 링크와 캐시 동작이 실제와 같다.

```bash

```

## 콘텐츠를 만드는 방법

데이터셋을 고르는 게 아니라 **추출 공식**을 고정해두면 새 데이터가 들어올 때마다
콘텐츠가 자동으로 나온다.

| 공식 | 로직 | 실제로 나온 것 |
|---|---|---|
| 극값 | `ORDER BY x DESC LIMIT 1` | 가장 긴 업소명 44자, 34년째 모범인 집 |
| 유일값 | `GROUP BY x HAVING COUNT = 1` | 딱 한 번만 쓰인 취소 사유 14,194가지 |
| 이름 | 정규식 · 낱말 세기 | '가든' 1,768곳, '할매' 251곳 |
| 자유 입력 | 사람이 손으로 적는 칸 | 「영업안함」 「포기」 「방충망 시설 불량」 |
| 수명 | 개업일 → 폐업일 | PC방 중앙값 3.1년, 최단 2일 |
| 사라진 칸 | 지금은 없는 서식 항목 | 「비디오재생기명 — 자동/수동」 |
| 데이터의 흠 | 범위 밖 · 형식 위반 | 지정일자 1911-11-11, 메뉴 칸의 '111' |

**옛 서식의 칸 이름**도 광맥이다. 비디오감상실 신청서의 「비디오재생기명」은 답이
자동/수동 둘뿐인데, 지금은 어느 서류에도 없는 질문이다.

가장 수확이 좋은 건 **자유 입력 필드**다. 규격이 없어서 담당자의 말투가 그대로 남는다.
모범음식점의 `지정취소사유`는 고유값이 16,094개, 그중 14,194개가 단 한 번만 등장한다.

### 광맥 스캐너

`scripts/scan.py`가 위 공식을 자동으로 돌린다. 아무 CSV나 넣으면 칸을 종류별로 갈라
(자유입력 · 사라진 칸 · 이름 · 날짜 · 식별자) 점수를 매긴다. `scan_all.py`는 그걸
208개 전부에 돌려 `data/광맥순위.txt`를 만든다.

**「사라진 칸」의 신호는 채움률이 아니라 쏠림이다.** 처음엔 '거의 안 채워진 칸'을 찾게
만들었는데 그건 틀렸다. 제3호의 제목이 된 「비디오재생기명」은 채움률이 72.5%나 된다.
진짜 신호는 **답이 두세 개뿐인데 한쪽으로 극단적으로 쏠린 것**이다 (자동 2,569 대 수동 62).

점수가 맞는지는 이미 발행한 열람실로 검증했다. 스캐너가 사람이 내린 편집 판단을
그대로 재현한다.

| 데이터셋 | 점수 | 스캐너가 찾은 것 | 실제로 쓴 각도 |
|---|---|---|---|
| 공중화장실 | 36 | 자유입력 「화장실명」 1회성 47,302건 | 개방시간 표기 36가지 (제4호) |
| 식품자판기 | 34 | 자유입력 「사업장명」 1회성 177,541건 | 서식이 묻는 회사 질문 (제7호) |
| 노래방 | 33 | 사라진 칸 「청소년실여부」 외 5개 | 노래연습장이라는 이름 (제6호) |
| 과속방지턱 | 28 | 자유입력 「설치장소」 1회성 30,151건 | 「도로」라고만 적은 47.8% (제5호) |
| 자전거보관소 | 24 | 사라진 칸 「수리대설치여부」 쏠림 99.8% | 수리대 35곳 (제8호) |
| PC방 | 19 | 자유입력 1회성 32,791건 | 작명과 수명 (제2호) |
| 비디오감상실 | 14 | 사라진 칸 「비디오재생기명」 쏠림 97.6% | 자동 또는 수동 (제3호) |
| 모범음식점 | 13 | 자유입력 「지정취소사유」 1회성 14,194건 | 취소 사유록 (제1호) |
| 동물병원 | 9 | 이름뿐. 자유입력 칸이 없다 | **미사용** |

**스캐너가 짚은 칸이 그대로 제목이 되지는 않는다.** 자전거보관소는 스캐너가
「수리대설치여부」를 골랐고 그게 제목이 됐지만, 노래방은 스캐너가 짚은
「청소년실여부」 대신 **상호에 적힌 이름**('노래연습장' 50,535 대 '노래방' 2,325)이
제목이 됐다. 스캐너는 어디를 팔지 알려줄 뿐이고, 무엇을 캘지는 사람이 정한다.

**점수는 정찰용 눈금일 뿐이다.** 극단적인 쏠림(99~100%)은 「다중이용업소여부: N 100%」처럼
아무도 안 쓰는 칸일 때가 많아 점수가 과하게 붙는다. 발행할 데이터셋이 정해지면
전용 `analyze_*.py`를 만들어 숫자를 처음부터 다시 센다.

## 열람실 하나 만드는 법

제4호부터 제8호까지 이 순서로 만들었다. 한 편에 대략 반나절.

**1. 후보 고르기** — `data/광맥순위.txt` 상위권을 보되 **점수만 믿지 않는다.**
   이미 쓴 열람실과 이야기가 겹치는지 먼저 본다. (식용얼음판매업이 41점으로 1위인데도
   제7호와 겹쳐서 뺐다.)

**2. 원본 받기** — `python scripts/fetch.py <slug> <한글이름>`
   slug는 `data/광맥순위.txt`에 있다. 스캔용으로 `data/raw/`에 이미 받아뒀다면
   그걸 `data/`로 복사해도 된다.

**3. 손으로 파보기** — 임시 스크립트로 칸을 훑는다. 여기서 **제목이 될 한 줄**을 찾는다.
   지금까지 제목이 된 것들은 전부 *서식이 물어본 이상한 질문*이거나 *사람이 손으로 적은 칸*이었다.

**4. `scripts/analyze_<이름>.py` 작성** — 페이지에 박을 숫자를 전부 여기서 계산하고
   `data/분석결과_<이름>.txt`로 뽑는다. **페이지의 모든 수치는 이 파일에서 나와야 한다.**
   나중에 원본이 갱신돼도 이걸 다시 돌려 검증할 수 있다.

**5. 페이지 만들기** — CSS는 `videoroom.html`의 `<style>` 블록을 통째로 물려받는다.
   생성 스크립트를 하나 짜서 숫자 배열 + 본문 템플릿으로 HTML을 뽑는 게 편하다
   (`%` 포맷 대신 `{{키}}` 치환을 써야 본문의 퍼센트 기호와 안 부딪힌다).

**6. 브라우저로 검증** — 콘솔 오류, 가로 넘침(`scrollWidth > innerWidth`),
   막대·표 개수, 링크가 실제 파일을 가리키는지. 그리고 **페이지 숫자를
   `분석결과_*.txt`와 하나씩 대조한다.** pandas 출력은 쉼표가 없으니 `4227` / `4,227`
   양쪽으로 찾아본다.

**7. 랜딩 등록** — `index.html`에서 **여덟 군데**를 고쳐야 한다. 하나라도 빠지면 숫자가 어긋난다.

   1. **직전 호의 큰 카드(`a.room form`)를 한 줄 목록(`a.room-lite`)으로 바꾼다.**
      큰 카드는 **최신 한 편만** 둔다. 접은 줄은 「지난 열람실」 머리 바로 뒤에 붙인다.
   2. 새 열람실의 큰 카드를 `<section class="blk">` 안 맨 위에 넣는다
   3. 데이터 서가 표 — `<tr>` 한 줄 추가
   4. 헤더 — `열람실 <em>N곳 개관</em>`
   5. 상단 바 — `분석 완료 <b>N개 데이터셋 M행</b>`
   6. 요약 지표 — `분석 완료 데이터셋` 숫자
   7. 요약 지표 — `읽은 데이터 행` 합계
   8. `const ROWS` 에 `"데이터셋명": 행수` 추가 + `const FACTS` 맨 앞에 지식 카드 몇 장

   `수록 지식` 숫자는 `FACTS.length`로 자동 계산되니 손대지 않는다.
   「계산 근거」 칸도 `ROWS`를 보고 카드마다 알아서 바뀐다.

   **왜 한 편만 큰 카드인가** — 카드 하나가 300px이라 8편이면 2,400px이다.
   30편이 되면 랜딩 스크롤의 대부분이 카드가 된다. 한 줄 목록은 편당 52px이라
   30편이어도 1,600px 안에 들어간다.

**8. 마무리** — `python scripts/sitemap.py` 실행하고, 이 README의
   「지금 어디까지 왔나」·폴더 트리·데이터 출처 표·다음 후보를 갱신한다.
   `about.html`의 「지금까지 연 열람실」 목록과 상단 지표(열람실 수·행 수)도 같이 고친다.

## 지켜야 할 선

- **취소 사유에는 상호를 붙이지 않는다.** "위생관리상태미흡"을 실명과 함께 띄우면
  잡학이 아니라 특정 가게 망신주기가 된다. 공개 데이터라도 하지 않는다.
  반대로 '34년째 모범'처럼 좋은 기록은 실명으로 쓴다. PC방 열람실도 같은 규칙을 따랐다.
- **이상치가 이야기를 가리면 범위를 자른다.** PC방 연도 그래프는 2008년 재등록 봉우리(15,393건)가
  나머지를 눌러버려서 2009년부터 그렸다. 자른 사실과 이유를 본문에 밝히고, 전체 연도는 표로 남겼다.
- **검수 없이 발행하지 않는다.** 공공데이터에는 오탈자·중복·좌표 오류가 흔하다.
  "가장 긴 도로명"이 사실은 입력 실수인 경우가 자주 나온다.
  틀린 잡학은 브랜드를 즉사시킨다.
- **모르는 건 모른다고 쓴다.** 「자동/수동」이 정확히 무엇을 가르는 구분이었는지는
  데이터에 없다. 그럴듯한 설명을 지어내면 그 순간 세모지는 인터넷 잡학이 된다.
- **출처를 반드시 표기한다.** 공공누리 의무이자, 이 서비스의 컨셉 그 자체다.

## 화면에 관해 정해둔 것

- **정부 문서 미학은 건드리지 않는다.** 모노 글꼴, 도장, 서식 박스, 절제된 색.
  화려하게 만들면 그냥 흔한 잡학 사이트가 된다. 이게 유일한 차별점이다.
- **본문 폭은 제한한다** (`max-width: 54~60ch`). 한 줄이 길면 눈이 다음 줄 첫머리를
  못 찾는다. 화면 끝까지 늘리는 게 더 나쁘다.
- **한국어 줄바꿈은 `word-break: keep-all`로 고정했다.** 브라우저 기본값은 한글을
  음절 단위로 아무 데나 잘라서 「직원」이 '직/원'으로 갈라진다.
  긴 영문 덩어리가 넘치지 않게 `overflow-wrap: break-word`를 짝으로 둔다.
  이 두 줄은 `body`에 있고 새 열람실은 `videoroom.html` 스타일을 물려받으니 자동으로 딸려온다.
- **첫 화면에 잡학 하나가 실제로 보여야 한다.** 사람들이 온 이유가 그것이다.
  헤드라인 아래 설명이 길어지면 「오늘의 세모지」 카드가 접히므로, 리드는 한 줄로 둔다.
- **표 안 스크롤은 최소로.** 모바일에서 손가락이 표에 걸리면 페이지가 안 내려간다.
  넓은 표는 `overflow-x:auto` 컨테이너에 넣되, 세로로 긴 목록은 별도 페이지로 뺀다.

## 배포

정적 파일뿐이라 어디에 올려도 된다. 페이지 간 링크는 전부 상대경로다.

**GitHub Pages**
1. 저장소를 만들고 이 폴더를 올린다 (`data/*.csv`는 `.gitignore`로 빠진다)
2. Settings → Pages → Source를 `main` 브랜치 루트로 지정
3. 개인 도메인을 쓰려면 Settings → Pages → Custom domain에 입력.
   저장하면 저장소 루트에 `CNAME` 파일이 자동으로 생긴다.
4. 도메인 등록기관(가비아·후이즈 등)에서 DNS 설정:
   - apex(`semoji.net`) → A 레코드 4개: `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`
   - `www` → CNAME `<username>.github.io`
5. Pages 설정에서 **Enforce HTTPS** 체크 (인증서 발급까지 몇십 분 걸릴 수 있다)

DNS 전파에 보통 10분~수 시간 걸린다.

## 아직 안 된 것

- **도메인을 아직 안 샀다.** `semoji.net`으로 쓰기로 하고 `robots.txt`·`sitemap.xml`에
  박아뒀다. 구매 전까지 이 파일들은 아무 일도 하지 않는다.
  `CNAME`은 일부러 만들지 않았다 — 도메인이 붙기 전에 만들어두면 GitHub Pages가
  기본 주소(`.github.io`)에서도 404를 뱉는다. Pages 설정에서 도메인을 넣으면 자동으로 생긴다.
- **구독 폼에 백엔드가 없다.** 이메일 형식만 검사하고 저장하지 않는다.
  화면에도 "아직 서버가 없어 저장되지 않습니다"라고 표시된다.
- **`ads.txt`가 없다.** AdSense 가입 후 발급되는 게시자 ID가 있어야 만들 수 있고,
  반드시 저장소 루트에 둬야 한다 (하위 폴더 불가).
- **AdSense 신청 전에 사이트가 인터넷에 살아 있어야 한다.** 심사할 URL이 없으면
  신청 자체가 안 된다. 도메인 구입 → 배포가 먼저다.
- **트래픽은 승인 요건이 아니다.** 구글은 최소 조회수 기준을 두지 않는다.
  요건은 독자적인 콘텐츠와 소개·연락처·개인정보처리방침 페이지다.
  권장 분량은 글 10~15편 수준인데 현재 14쪽이라 이미 넘겼다.
  다만 **승인은 자격일 뿐 수익이 아니다.** 트래픽이 없으면 승인받아도 0원이라,
  네이버 서치어드바이저 등록이 실제로는 더 급하다.
- **네이버 서치어드바이저에 등록하지 않았다.** 국내 검색 유입의 출발선이다.
